# Evidence Routing

对每条输入评论恰好返回一个 Evidence Atom。只能使用输入已有的 `comment_id` 和完整
`SourceReference`，不得遗漏、重复、改写或捏造它们。

`route` 只能是 `BRAND`、`PRODUCT`、`SERVICE`、`SCENE`、`COMPETITOR` 或 `OTHER`，六类互斥。按原文的核心评价对象单选，不设置固定优先级；产品或服务问题不得强改为品牌问题；单条证据不得推出品牌战略或候选。

## Route：核心评价对象

- `PRODUCT`：口味、甜度、酒精感、包装、规格、调饮结果或其他产品体验。
- `SCENE`：真实发生的饮用行为、饮后身体反应、醉酒状态和酒桌社会行为，以及与这些行为直接相关的时间、地点、同行者、送礼或用餐情境。酒饮相关的饮用人群、饮用方式、敬酒或酒桌社会行为，只要是评论核心，即使没有明确时间、地点、第一人称或“已经喝过”，也归为 `SCENE`；酒精影响下的身体或情绪状态同样归为 `SCENE`。若核心是产品本身的口味、甜度、酒精感、包装、规格或调饮结果，仍归为 `PRODUCT`。
- `BRAND`：品牌印象、身份认同、价值观，或与明确品牌绑定的饮酒文化态度。整体性品牌判断也归为 `BRAND`：评论的核心结论是对品牌的总体评价、品牌适合什么人、品牌值得信任或值得选择（例如“这个品牌可以的”“适合女生/适合大众”“被这个品牌圈粉了”“性价比很高的品牌”），即使其中列举口感、度数、配料等产品细节作为支撑；此时不得因存在产品细节而改判 `PRODUCT`。只有核心结论就是具体产品体验本身、不含任何整体品牌判断时，才归 `PRODUCT`。
- `SERVICE`：渠道、库存、配送、客服或购买过程。
- `COMPETITOR`：明确非目标品牌、竞品产品或替代选择，且比较、替代或竞争是评论的中心问题。
- `OTHER`：与研究相关但核心对象不属于以上五类，例如完全脱离具体饮酒行为、饮酒方式、酒桌行为和饮后状态的通用酒精健康、安全、科普、政策或泛化社会规范讨论；仅询问推荐、表达想去或尚未发生的场景，也归为 `OTHER`。

品牌名称出现不等于 `BRAND`，饮用地点出现不等于 `SCENE`。明确提到竞品不等于 `COMPETITOR`；只有竞品比较、替代选择或竞争本身是中心结论时才选 `COMPETITOR`。明显无关内容不得用 `OTHER` 承接，应让整批失败并回到清洗层。

复合评论使用一个判断：“如果只能保留一句，哪一句最能代表评论者真正想表达的结论？”

## Experience Scope：原文明示的体验

`experience_scope` 只根据原文明示内容判断，不得根据常识、语气或可能性推断：

1. 第一人称体验，或直接口感判断、调饮结果或饮后感受，均可判为 `ACTUAL_USE`；不强制要求出现“我喝过”。
2. 明示已经购买、但未饮用或未说明饮用，判为 `PURCHASE_ONLY`。
3. 明示未饮用，且不存在已购买未使用事实，判为 `NON_USE`。
4. 泛化宣传、第三方转述或没有体验立场的产品描述，仍为 `UNKNOWN`。

`ai_confidence` 只表示你对路由分类的把握，绝不能用 confidence 提升或替代 Evidence Grade。

## Evidence Grade：信息链完整度

`evidence_grade` 只表示证据质量，不表示观点正负、是否实际饮用或模型置信度：

- A 级必须形成完整、可复核的信息链：评价对象、具体情境或依据，以及明确判断均能从原文找到。多个形容词本身不足以构成 A。
- B：判断明确，但信息链不完整，例如缺少具体情境、依据或可复核细节。
- 仅有购买意向、口号或单一笼统判断通常为 C；简单情绪或低信息量信号也为 C。

必须提供简洁的 `explanation`，且不得补充输入以外的品牌、产品、服务或竞品事实。只返回符合指定 JSON Schema 的 JSON，不得输出 Markdown、分析过程或额外文字。

## 离线批量标注模式：输出封套

当调用方明确要求返回 `batch_id`、`input` 和 `annotations` 时，使用离线批量标注模式，不要返回在线模式的 `atoms` 封套：

- `batch_id` 必须原样复制当前任务的批次 ID。
- `input` 必须逐字逐字段复制任务输入，不能排序、删改或补充记录。
- `annotations` 必须与 `input` 数量相同、顺序一致、ID 一一对应。每条 annotation 必须原样重复输入中的六个字段：`raw_id`、`raw_content`、`source_platform`、`source_id`、`source_type`、`source_ref`；六个输入字段均不可省略、改写或捏造，尤其 `raw_content` 不可省略。
- 在上述六个输入字段之外，annotation 只能增加 `route`、`experience_scope`、`evidence_grade`、`ai_confidence` 和 `explanation`；不得增加其他字段。
- 每条 annotation 的 `ai_confidence` 必须严格填写 `0.5`、`0.7` 或 `0.9` 之一，不得填写其他小数。
- `explanation` 必须严格使用 `核心对象：...；体验：...；证据强度：...。` 三段格式；不得改成自由发挥的一句话，不得省略任一段。
- 在线 API 模式由调用方要求返回 `atoms` 时，遵循调用方提供的 JSON Schema，不返回离线批量标注封套。
